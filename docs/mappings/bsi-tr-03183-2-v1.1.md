# BSI TR-03183-2 v1.1: mapping to CycloneDX and SPDX 2.x

Status: awaiting owner review

Version labels verified against the bundled schemas in src/sbom_validation/formats/schemas (CycloneDX 1.4-1.7, SPDX 2.3).

Source: BSI TR-03183-2 version 1.1 (English, 2023-11-28), sections 3.1, 3.2, 4,
5.1, 5.2 and 5.3. This file is the draft mapping from each requirement to the
SBOM elements the validator examines. Later implementation tasks (format
loaders, rule data, rules) build against it. Paths are JSON paths; `[*]` means
every array element. CycloneDX paths hold for 1.4 and higher unless noted; SPDX
paths hold for SPDX 2.3 JSON.

Conventions:

- Alternatives within one cell are tried together; the requirement passes if
  any one alternative satisfies it (design section 12, Aggregation).
- "Components" means every component examined: for CycloneDX the primary
  component `metadata.component` plus every entry of `components[*]`
  (recursively through nested `components[*].components[*]`); for SPDX every
  entry of `packages[*]` (the primary package included).
- Email-or-URL check: a value passes as an email if it has a valid address
  form, otherwise as a URL if it parses as an absolute URL with a scheme and
  host.
- Levels: "Level" is taken from the guideline text. "Conditional" means MUST
  if it exists and its prerequisites are fulfilled; present values are checked
  for form, absence is neither an error nor reported.

## Format detection (used by REQ_BSI11_FORMATS)

| Format | Detection | Version element |
| --- | --- | --- |
| CycloneDX JSON | `bomFormat` equals `"CycloneDX"` | `specVersion` (for example `"1.4"`) |
| SPDX 2.x JSON | `spdxVersion` starts with `"SPDX-2."` | `spdxVersion` (for example `"SPDX-2.3"`) |
| SPDX 3.x | JSON-LD document with `@context` referring to SPDX 3 | not supported in the first release; reported as an unsupported format, not a spec failure |

## REQ_BSI11_FORMATS (section 4)

Rule: the format is CycloneDX with `specVersion` 1.4 or higher, or SPDX with
`spdxVersion` 2.3 or higher.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `bomFormat`, `specVersion` |
| SPDX 2.x | `spdxVersion` |

A schema-valid file in a lower version (CycloneDX 1.3, SPDX 2.2) is a failed
row. Other rules that need the format are reported as not evaluated.

## REQ_BSI11_DEPTH (section 5.1, recursive dependency resolution)

Not verifiable: whether resolution reached the first component outside the
scope of delivery on every path cannot be decided from the SBOM alone.
Elements shown for the reviewer, not evaluated:

| Format | Elements |
| --- | --- |
| CycloneDX | `dependencies[*].ref`, `dependencies[*].dependsOn[*]` |
| SPDX 2.x | `relationships[*]` (types `DEPENDS_ON`, `DEPENDENCY_OF`, `CONTAINS`, `CONTAINED_BY`) |

## REQ_BSI11_BUILD (section 5.1, Build SBOM)

Not verifiable: whether the SBOM was created in the build process cannot be
decided from the SBOM alone. Elements shown for the reviewer, not evaluated:

| Format | Elements |
| --- | --- |
| CycloneDX | `metadata.lifecycles[*].phase` (1.5 and higher; `build` is an informative hint only), `metadata.tools` |
| SPDX 2.x | `creationInfo.creators[*]` (entries beginning `Tool:`), `creationInfo.comment` |

## REQ_BSI11_SBOM_CREATOR (section 5.2.1, creator of the SBOM)

Rule: an email address of the entity that created the SBOM; a URL if no email
address is available.

| Format | Elements examined (alternatives) |
| --- | --- |
| CycloneDX | `metadata.authors[*].email` (1.4 and higher; `metadata.authors` is `organizationalContact`) |
| | `metadata.manufacture.contact[*].email` (1.4 and higher, deprecated in 1.6; `metadata.manufacture` is `organizationalEntity`; `manufacturer` replaces it in 1.6 and higher) |
| | `metadata.manufacturer.contact[*].email` (1.6 and higher) |
| | `metadata.supplier.contact[*].email` |
| | URL fallback: `metadata.authors[*]` has no URL field, so use `metadata.manufacture.url[*]`, `metadata.manufacturer.url[*]`, `metadata.supplier.url[*]` |
| | `metadata.tools` entries (name only, not accepted as the creator) |
| SPDX 2.x | `creationInfo.creators[*]` entries of the form `Person: <name> (<email>)` or `Organization: <name> (<email>)`: the email is the text inside the final parentheses |
| | URL fallback: none defined by the creators syntax; a `Person:` or `Organization:` entry whose parenthesised value is a URL, if present, is accepted |
| | `Tool:` entries are not accepted as the creator |

## REQ_BSI11_TIMESTAMP (section 5.2.1)

Rule: date and time of SBOM data compilation, in the form the format specifies
(RFC 3339 date-time, as for the format's own schema).

| Format | Element examined |
| --- | --- |
| CycloneDX | `metadata.timestamp` (ISO 8601 / RFC 3339 date-time) |
| SPDX 2.x | `creationInfo.created` (`YYYY-MM-DDThh:mm:ssZ`) |

## REQ_BSI11_CMP_CREATOR (section 5.2.2, component creator)

Rule: email address of the entity that created and maintains the component; a
URL if no email address is available. Checked per component.

| Format | Elements examined (alternatives) |
| --- | --- |
| CycloneDX | `components[*].authors[*].email` (1.6 and higher; `authors` and `manufacturer` on components were added in 1.6) |
| | `components[*].author` (1.4 and higher, deprecated in 1.6; free text; accepted only if it contains an email address in angle brackets or as a bare address) |
| | `components[*].manufacturer.contact[*].email` (1.6 and higher) |
| | `components[*].supplier.contact[*].email` |
| | `components[*].publisher` (free text, same acceptance as `author`) |
| | URL fallback: `components[*].manufacturer.url[*]`, `components[*].supplier.url[*]`, `components[*].externalReferences[*].url` of type `website` |
| | The same paths apply to `metadata.component` |
| SPDX 2.x | `packages[*].originator` of the form `Person: <name> (<email>)` or `Organization: <name> (<email>)` |
| | `packages[*].supplier` of the same form (a supplier is the vendor and is accepted only as an alternative where no originator is present) |
| | URL fallback: `packages[*].homepage`, or a URL in the parenthesised part of `originator` |

Note: the guideline distinguishes the creator (originator/author) from the
vendor (supplier). Whether `supplier` may stand in for the creator is a
point for owner review.

## REQ_BSI11_CMP_NAME (section 5.2.2)

| Format | Element examined |
| --- | --- |
| CycloneDX | `components[*].name` (required by the schema; additionally non-empty); `metadata.component.name` |
| SPDX 2.x | `packages[*].name` (required by the schema; additionally non-empty) |

## REQ_BSI11_CMP_VERSION (section 5.2.2)

Rule: a non-empty version identifier is present. The Semantic or Calendar
Versioning recommendation is a SHOULD and is not reported.

| Format | Element examined |
| --- | --- |
| CycloneDX | `components[*].version`; `metadata.component.version` |
| SPDX 2.x | `packages[*].versionInfo` |

## REQ_BSI11_CMP_DEPS (section 5.2.2, dependencies)

Rule: the SBOM records the components each component directly depends on.
The check requires dependency data to exist: for CycloneDX a `dependencies[*]`
entry for the component, for SPDX at least one dependency relationship with
real endpoints in the document (judged document-wide). Whether references
resolve to a component in the SBOM is not checked (see open points);
completeness cannot be checked and is reported as not verifiable.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `dependencies[*].ref` (matches `components[*].bom-ref` or `metadata.component.bom-ref`), `dependencies[*].dependsOn[*]`, and in 1.6 and higher `dependencies[*].provides[*]` |
| | The check requires each component to have a `dependencies[*]` entry whose `ref` matches its `bom-ref`; a missing entry is a failure. An empty `dependsOn` is a valid statement of "no dependencies" |
| SPDX 2.x | `relationships[*]` with `relationshipType` `DEPENDS_ON` (source = dependent in `spdxElementId`, target in `relatedSpdxElement`) or `DEPENDENCY_OF` (inverse direction) |
| | `relatedSpdxElement` values of `NONE` and `NOASSERTION` are not accepted as a statement of dependencies |
| | Also considered as structure: `CONTAINS`, `CONTAINED_BY`, `STATIC_LINK`, `DYNAMIC_LINK` |

## REQ_BSI11_CMP_LICENCE (section 5.2.2)

Rule: licences are identified by SPDX licence identifiers or expressions; a
`LicenseRef-scancode-` identifier for ScanCode LicenseDB licences; otherwise a
`LicenseRef-<entity>-` identifier. Validated against the pinned SPDX licence
list. Whether the stated licence is the correct one is not verifiable.

| Format | Elements examined (alternatives) |
| --- | --- |
| CycloneDX | `components[*].licenses[*].license.id` (an SPDX identifier) |
| | `components[*].licenses[*].license.name` (accepted only if it is a `LicenseRef-` identifier of the permitted prefixes) |
| | `components[*].licenses[*].expression` (SPDX licence expression) |
| | The same paths apply to `metadata.component` |
| SPDX 2.x | `packages[*].licenseDeclared` (SPDX identifier, expression or `LicenseRef-`) |
| | `packages[*].licenseConcluded` (same forms; `NOASSERTION` and `NONE` do not satisfy the rule) |
| | `hasExtractedLicensingInfos[*].licenseId` (must exist for each `LicenseRef-` used) |

`NOASSERTION` and `NONE` are not accepted as a licence identification.

## REQ_BSI11_CMP_HASH (section 5.2.2, hash of the executable component)

Rule: a SHA-256 hash of the component in its executable form.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `components[*].hashes[*]` with `alg` equal to `"SHA-256"` and `content` a 64-character hexadecimal string; `metadata.component.hashes[*]` |
| SPDX 2.x | `packages[*].checksums[*]` with `algorithm` equal to `"SHA256"` and `checksumValue` a 64-character hexadecimal string |
| | `packages[*].files` and `files[*].checksums[*]` are not examined for this rule |

Which hash refers to the executable form, as against the source, cannot be
told from the plain hash fields. See REQ_BSI11_SRC_HASH for how the two are
kept apart.

## REQ_BSI11_SBOM_URI (section 5.3.1)

Conditional: when present, a valid URI.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `serialNumber` (a `urn:uuid:` URI), or, as an alternative, `externalReferences[*].url` of type `bom` at the top level (1.4 and higher); `metadata.component.externalReferences[*]` is not used |
| SPDX 2.x | `documentNamespace` (a URI) |

## REQ_BSI11_SRC_URI (section 5.3.2, source code URI)

Conditional: when present, a valid URI.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `components[*].externalReferences[*].url` where `type` is `vcs` (1.4 and higher) |
| | `components[*].externalReferences[*].url` where `type` is `distribution-intake` is not used |
| SPDX 2.x | `packages[*].sourceInfo` is free text and is not used |
| | `packages[*].externalRefs[*]` of `referenceCategory` `OTHER` with a repository URL is not defined by the schema and is not used |
| | `packages[*].downloadLocation` where it is a VCS location (`git+`, `hg+`, `svn+`, `bzr+` prefix) |

## REQ_BSI11_EXE_URI (section 5.3.2, URI of the executable form)

Conditional: when present, a valid URI.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `components[*].externalReferences[*].url` where `type` is `distribution` (or `distribution-intake`, 1.5 and higher) |
| SPDX 2.x | `packages[*].downloadLocation` where it is not a VCS location and is not `NONE` or `NOASSERTION` |

## REQ_BSI11_SRC_HASH (section 5.3.2, SHA-256 of the source code)

Conditional: when present, a 64-character hexadecimal SHA-256.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `components[*].externalReferences[*].hashes[*]` with `alg` `"SHA-256"` on references of type `vcs` or `source-distribution` (`hashes` on external references exist since 1.4; the `source-distribution` type was added in 1.6, so in 1.4 and 1.5 only `vcs` references carry such hashes) |
| SPDX 2.x | `packages[*].checksums[*]` with `algorithm` `"SHA256"` where a separate source-code package or `packages[*].filesAnalyzed`/`packageVerificationCode.packageVerificationCodeValue` (SHA-1, not accepted) identifies the source; otherwise not distinguishable |

The standard formats have no dedicated source-hash field in all versions. This
mapping is the weakest in the file and is flagged for owner review: where
source and executable hashes cannot be told apart, the rule reports nothing.

## REQ_BSI11_OTHER_IDS (section 5.3.2, CPE and purl)

Conditional: when present, a syntactically valid CPE (2.2 or 2.3) or purl.

| Format | Elements examined |
| --- | --- |
| CycloneDX | `components[*].cpe` (CPE 2.2 URI or 2.3 formatted string), `components[*].purl` (Package URL) |
| SPDX 2.x | `packages[*].externalRefs[*]` with `referenceCategory` `SECURITY` and `referenceType` `cpe22Type` or `cpe23Type`, value in `referenceLocator` |
| | `packages[*].externalRefs[*]` with `referenceCategory` `PACKAGE-MANAGER` (the SPDX 2.3 JSON schema accepts only the hyphenated spelling `PACKAGE-MANAGER`) and `referenceType` `purl`, value in `referenceLocator` |

## REQ_BSI11_ONE_PER_VERSION (section 3.1)

Not verifiable: whether a separate SBOM exists for each software version
cannot be decided from one SBOM. Elements shown for the reviewer:

| Format | Elements |
| --- | --- |
| CycloneDX | `version` (the SBOM document version), `metadata.component.version` |
| SPDX 2.x | `documentNamespace`, `packages[*].versionInfo` of the primary package |

## REQ_BSI11_COMPONENT_EXEC (section 3.2)

Not verifiable: the guideline defines a component as a single executable file
and the validator does not detect "executable" itself. Every component in the
SBOM is checked (design section 12). Elements shown for the reviewer:

| Format | Elements |
| --- | --- |
| CycloneDX | `components[*].type` (`application`, `library`, `framework`, `file` and others) |
| SPDX 2.x | `packages[*].primaryPackagePurpose` (2.3) |

## Open points for the owner

1. Whether SPDX `packages[*].supplier` and CycloneDX `supplier` may stand in
   for the component creator (REQ_BSI11_CMP_CREATOR).
2. Whether URL fallbacks are drawn from `homepage` and `website` references.
3. How to tell executable hashes from source hashes (REQ_BSI11_CMP_HASH,
   REQ_BSI11_SRC_HASH).
4. Whether `metadata.component` and the SPDX primary package are examined as
   components (design section 12 says yes).
5. Whether CycloneDX `serialNumber` is accepted as the SBOM URI.

Not implemented (open points, not checked by the validator):

6. Dependency reference resolution (REQ_BSI11_CMP_DEPS): whether
   `dependsOn` and `relatedSpdxElement` values resolve to a component in the
   SBOM. Not checked, to avoid false errors: SPDX targets may be files,
   snippets or external `DocumentRef-` elements, and CycloneDX `dependsOn` may
   point at services.
7. The `hasExtractedLicensingInfos[*].licenseId` entry for each `LicenseRef-`
   used (REQ_BSI11_CMP_LICENCE): not checked.
8. A CPE string in a CycloneDX `purl` field (or the reverse) passes
   REQ_BSI11_OTHER_IDS: the model does not record which kind each identifier
   is, so a value is accepted if it is a valid purl or a valid CPE.
